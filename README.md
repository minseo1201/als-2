# FRAME — 동의 기반 영상·조도 실험

참가자 동의를 먼저 받고, 영화 목록 형태의 화면에서 기존 패턴 영상 2개를 재생하는 연구용 웹사이트입니다. 화면 제목은 **국내 영화**, 영상 제목은 **영화1 / 영화2**입니다. 실제 영화·카메라·마이크를 사용하는 것은 아닙니다.

## 화면 흐름

1. **참여 안내:** 수집 항목, 기록 시간, 실제 저장 방식, 중단 방법을 알립니다. 체크박스는 기본 해제입니다.
2. **국내 영화:** 영화1·영화2 카드. 하단에 연구 참여 상태, 센서 확인, 연구 설정, 참여 안내, 동의 철회 메뉴가 있습니다.
3. **영상 선택:** 준비 확인 후 5초 카운트다운부터 Lux를 기록합니다. 영상 내용은 이전 버전과 같습니다.
4. **재생:** 영상 종료 시 기록을 멈춥니다. ‘실험 중단’ 버튼 또는 Esc로 중단할 수 있습니다.
5. **결과:** 저장 성공·실패와 복구 방법을 표시합니다. ‘다음 측정 진행하기’는 영상 선택으로 돌아갑니다.

동의 전 센서 연결·측정 데이터 전송은 차단됩니다. 접속 시 공개 수신 설정만 확인하며, 동의했다고 즉시 센서를 켜지는 않습니다. 동의 시각과 안내 버전을 메타데이터에 보관합니다. 새 접속·새로고침에서는 다시 동의해야 합니다. 철회하면 이후 수집은 차단됩니다. 중단 전에 수집한 데이터는 저장되며, 이미 저장한 데이터 삭제 요청은 실험 진행자가 처리합니다.

## A. 연구자 컴퓨터에 저장 — Node 수신 서버

Node.js 20 이상이 설치된 **연구자 컴퓨터**에서 이 폴더를 열고 실행합니다. 추가 패키지는 필요하지 않습니다.

```powershell
node server.js
```

- 참가자 페이지: `http://localhost:8000/`
- 연구자 기록 화면: `http://localhost:8000/researcher.html`
- 저장 위치: 서버 실행 컴퓨터의 `server-data/실험ID/`
- 연구자 접근 키: 실행 터미널에 표시. 참가자에게 전달하지 않습니다.

서버가 참가자 페이지와 수신 API를 함께 제공합니다. 참가자가 동의하고 영상을 선택하면 실험별 업로드 키를 발급합니다. 시청 중 약 2초마다 새 센서·프레임·이벤트 기록을 전송하며, 종료 시 남은 데이터와 종료 정보를 전송합니다. 서버가 CSV·JSON 저장을 완료한 후에만 저장 완료로 표시합니다. 참가자에게 폴더 선택을 요구하지 않습니다.

### 다른 컴퓨터에서 접속하기

`localhost`는 각자의 컴퓨터를 가리킵니다. 참가자에게 연구자 PC의 `localhost` 주소를 보내면 연결되지 않습니다. 참가자가 접근할 수 있는 **신뢰된 HTTPS 주소**에서 이 Node 서버를 제공해야 합니다. 외부 참가자가 `http://연구자IP:8000`로 열면 ALS가 요구하는 보안 컨텍스트를 충족하지 못할 수 있습니다.

수신 서버의 외부 배포는 아직 수행하지 않았습니다. 연구실 HTTPS 프록시 또는 서버 호스팅에 연결한 후 참가자에게 해당 주소를 전달하세요. 사이트와 API는 같은 출처에서 실행하도록 구성했습니다. GitHub Pages 화면에서 다른 수신 주소를 임의로 지정하는 방식은 현재 지원하지 않습니다.

| 환경변수 | 기본값 / 용도 |
| --- | --- |
| `PORT` | `8000` |
| `HOST` | `127.0.0.1`. 네트워크 수신이 필요한 환경에서 명시적으로 지정 |
| `ALS_DATA_DIR` | 프로젝트의 `server-data` |
| `ALS_RECEIVER_LABEL` | `연구자 컴퓨터`. 참가자 안내에 표시할 실제 저장 대상 이름 |
| `ALS_ADMIN_TOKEN` | 미지정 시 무작위 생성. 연구자 조회·다운로드용 |
| `ALS_PUBLIC_ORIGIN` | HTTPS 프록시 사용 시 참가자 접속 출처. 예: `https://study.example.edu` (후행 `/` 없이) |
| `TLS_KEY_FILE`, `TLS_CERT_FILE` | 직접 HTTPS 제공 시 신뢰된 인증서 파일 경로 |

클라우드에 수신 서버를 실행하면 데이터는 클라우드 서버 디스크에 저장됩니다. **연구자 노트북에 직접 저장**하려면 그 노트북에서 수신 서버를 실행하고 HTTPS 접속 경로를 구성해야 합니다. 클라우드 기록을 연구자 화면에서 내려받는 방법도 가능합니다.

이 수신기는 통제된 실험용입니다. 한 실험 최대 100,000행, 요청 본문 최대 2MiB, 동시 미완료 세션 최대 100개로 제한합니다. 공개 서비스용 사용자 계정·참가자 모집·보관 기간 관리 기능은 포함하지 않습니다. 자동 삭제 기한은 없으므로 실험 진행자가 연구 보관 계획에 따라 파일을 관리하세요.

## B. 로컬 저장 — 기존 정적 사이트 / GitHub Pages

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

`http://127.0.0.1:8000`에서 실행합니다. `/api/config`가 404인 정적 호스팅에서는 로컬 모드로 동작합니다. 안내에도 **서버로 전송하지 않는 로컬 저장**이라고 표시합니다. 영상 선택 시 참가자 컴퓨터의 저장 폴더를 요청합니다. `index.html` 더블클릭 실행은 지원하지 않습니다.

**GitHub Pages에 올리는 것만으로 연구자 컴퓨터에 데이터가 들어오지는 않습니다.** 원격 수집에는 A 방식의 수신 서버가 필요합니다.

## 수집 항목과 파일

- `als_raw.csv`: 센서 시각(ms), 콜백 시각(ms), 전달 지연(ms), 첫 관측 프레임의 표시 예정 시각 기준 상대 시간(ms), Lux.
- `video_frames.csv`: 콜백 시각(ms), 영상 시각(초), 합성 제출 시각(ms), 표시 예정 시각(ms), 누적 프레임 카운터.
- `events.csv`: 재생 요청·대기·탐색·종료 등 사건 시각.
- `session.json`: 동의 버전·시각·저장 방식, 영상 해시, 브라우저·화면 환경, 실험 코드·메모, 종료 사유와 이벤트 통계.

연구자 수신 모드에는 `record.json`과 순번별 원본 전송 파일 `batches/`도 남습니다. 미완료 기록은 연구자 화면에서 ‘수신 중 / 중단 가능’으로 표시합니다. 연구자 다운로드는 원본 배열이 포함된 JSON이며 CSV 4개는 서버 저장 폴더에도 존재합니다. CSV는 UTF-8 BOM을 포함합니다.

카운트다운 구간은 음수 상대 시간이 될 수 있습니다. 네트워크 도착 시각을 센서 시각 대신 쓰지 않습니다. 화면 크기 변경·탭 숨김·센서 오류·영상 오류·10초 이상 영상 정체는 중도 종료로 기록합니다.

## 통신 오류와 복구

참가자 브라우저는 약 2초마다 IndexedDB에 복구본을 남깁니다. 전송 실패 시 같은 순번을 재시도하며 서버는 중복 저장을 방지합니다. 네트워크 요청이 대기열에 계속 쌓이지 않도록 한 번에 한 요청만 진행합니다.

최종 전송 실패 시 서버 저장 완료로 표시하지 않습니다. 결과 화면이나 연구 설정에서 JSON을 다운로드하거나 재전송할 수 있습니다. 복구본 재전송은 별도 ID로 저장하며 `recovered_from`에 이전 ID를 기록합니다. 서버 재시작 시 기존 업로드 키는 만료되지만 받은 배치 파일은 남습니다. 부분 기록과 복구본을 별개의 독립 측정으로 세지 마세요.

강제 종료·전원 장애 시 마지막 체크포인트 이후 데이터가 손실될 수 있습니다. 동의 철회는 이미 저장한 기록을 자동 삭제하지 않습니다. 브라우저 복구본과 서버 데이터를 각각 관리해야 합니다.

## 영상과 센서 제약

| 표시 제목 | 실제 파일 | 재생 정보 |
| --- | --- | --- |
| 영화1 | `videos/ALS_30_patterns_3s_pattern_3s_black.mp4` | 1280×720 / 10fps / 1800프레임 / 180초 |
| 영화2 | `videos/ALS_30_patterns_paper_style.mp4` | 1280×720 / 12fps / 180프레임 / 15초 |

이전에 변환한 H.264 웹용 복사본을 그대로 사용합니다. 외부의 사용자 원본은 변경하지 않았습니다. 픽셀 무손실 변환은 아니며 검증 결과는 `videos/encoding-report.json`에 있습니다. 웹·앱 비교에는 같은 파일을 사용하세요.

실제 ALS가 있고 브라우저에서 접근 가능한 기기에서만 측정할 수 있습니다. 100Hz는 요청값이며 보장되지 않습니다. 센서가 없는 노트북에서도 동의·목록 화면은 볼 수 있지만 측정은 실패합니다. 브라우저 권한 제한을 우회하지 않습니다.

영상 표시 예정 시각은 실제 발광 시각이 아닙니다. 센서 적분·응답 지연도 별도 보정이 필요합니다. 자동 밝기·콘텐츠 기반 밝기·HDR·야간 모드·거리·각도·주변 조명을 고정하세요. 카운트다운 숫자와 작은 중단 버튼도 광 자극이므로 반복 간 같은 조건을 유지하세요.

관련 규격: [Generic Sensor](https://w3c.github.io/sensors/), [영상 프레임 콜백](https://wicg.github.io/video-rvfc/), [File System Access](https://wicg.github.io/file-system-access/).

## GitHub 업로드

기존 코드와 함께 **`ui.js`, `remote.js`, `server.js`, `researcher.html`, `researcher.js`**도 올려야 합니다. `.tools/`, `server-data/`, 인증서·개인 키·환경변수 파일은 올리지 마세요. 웹에서 직접 업로드할 때 `.gitignore`가 자동 제외해 주지 않습니다.

GitHub Pages는 로컬 모드입니다. 브랜치 `main`, 폴더 `/(root)`를 지정하며 최상위에 `index.html`이 있어야 합니다. 이번 수정에서는 커밋·푸시·외부 배포를 수행하지 않았습니다.

## 검증

```powershell
npm test
node --check app.js
node --check remote.js
node --check server.js
```

검사는 동의 전 차단·철회, 시간 정렬, 원격 전송 분기, 수신 API와 실제 임시 폴더 저장, 권한 분리, 중복 재전송, 미완료 복구를 다룹니다. API 검사는 요청·응답 경계를 직접 실행하므로 실제 네트워크 소켓·HTTPS를 입증하지는 않습니다. 화면 흐름 검사도 센서·DOM 경계를 대체하므로 실물 ALS·브라우저 화면 배치·두 기기 통신은 별도 확인이 필요합니다.
